**Stack (pinned 2026-10-28/29, newer majors than most docs):** React 19.3, Vite 8 (`@vitejs/plugin-react` 6), Vitest 5 + jsdom 30, React Router 8 — import everything from `react-router` (declarative mode: `BrowserRouter`, `Routes`, `Navigate`, `Outlet`, `Link`, `MemoryRouter`, `useParams`, `useNavigate`), TypeScript 6, ESLint 10 flat config + `eslint-plugin-react-hooks` 7 (React-Compiler rules: no synchronous `setState` in an effect), Tailwind 4 + daisyUI 5. npm 12 blocks install scripts (`fsevents`) — harmless. Run `npm --prefix frontend run format` once before the gates (Prettier reflows long lines in new files).

**Tests:** Vitest without globals → `src/test-setup.ts` calls `cleanup()` itself and sets `configure({ testIdAttribute: 'id' })` so `getByTestId('sign-in-email')` ⇒ `#sign-in-email`. Reuse `src/test-utils.tsx` (`createMockServices` — `listWallets`/`listCurrencies` default to `[]`, so any container that loads them renders in unrelated specs — `renderWithProviders`, `deferred`). Containers are tested by rendering `<App />` at a route with only the services mocked. Pitfalls hit: jest-dom's `toHaveTextContent` **normalises the no-break space** (assert money with `element.textContent` and `' '`); `vi.useFakeTimers({ toFake: ['Date'] })` fixes "today" without freezing Testing Library's waits; `it.each([...] as const)` makes rows readonly and breaks typed props (annotate the table instead); `Intl.NumberFormat.format()` takes a decimal **string** only as the `` `${number}` `` type (cast the string you built from digits). `grep --include` globs must be quoted in this zsh (`--include='*.ts'`).

**Layout of F-2 code to extend:** `src/services/http/` (`sendJson`, `toApiError`, `ApiError`, `GENERIC_FAILURE_TEXT` — shared by every HTTP service), `src/services/wallets/` (types, `HttpWalletService`, messages, typed-text→request presenters), `src/money/` (pure money/date helpers), `src/hooks/use-async-value.ts` (loading/loaded/failed; the loader must be a `useCallback`), humble `components/` + containers in `pages/`. Money is a decimal-integer string end to end; digits from `GET /currencies`; never a float.

**Design tokens live in ONE file, `frontend/src/styles/theme.css`** (primitive `@theme static` → semantic daisyUI themes `ledger` / `ledger-night` → component radii/size/border). Direction "household ledger" (paper + ink + bookkeeping green, Newsreader over Source Sans 3, double rule under `h1`, hairline under `h2`). Later features: use semantic classes only (`bg-base-100`, `btn-primary`, `text-success`, `text-error`, `alert-error`), add tokens there, don't invent a second palette. Fonts are self-hosted `@fontsource-variable/*` (no runtime third-party font request — keeps E2E offline-safe). One `btn-primary` per screen.

**daisyUI 5 pitfalls hit:** (1) page background must be set through `:root { --root-bg: var(--color-base-200) }`, not `body`. (2) default `.input` border is 20% content ≈ 1.4:1 — use `border-base-content/60` (≥3:1). (3) `.alert` is a column grid — several message lines need `alert-vertical justify-items-start text-start gap-2` (`ErrorList` has it). (4) `.input` default font is 14 px (iOS zoom) — use `input-lg`; `.list` is 14 px too — add `text-base`. (5) layout utilities (`@layer utilities`) beat daisyUI's component layer, so plain Tailwind overrides component defaults without `!`. (6) **a checked `btn` radio is primary-coloured by default** — override with `checked:[--btn-color:…] checked:[--btn-fg:…]`; use the inverse pair (`base-content` on `base-100`) so selected-vs-unselected stays ≥3:1 in both schemes (`neutral` is ~1.4:1 from `base-200` in dark). (7) Tailwind 4: `wrap-anywhere` for text a person typed, `data-negative:` for a value-less data attribute, `not-last:border-b`, `group-data-[kind=income]:…`.

**React gotchas:** a ref callback that focuses its element must be a stable module-level function (`focus-on-mount.ts`) — an inline arrow is re-run on every render and steals focus from the field being typed in. `fetch` must be wrapped, never stored bare (`this.fetchFn()` ⇒ "Illegal invocation"). Derive "loading" instead of setting state in an effect (`useAsyncValue` keeps the answer with the loader it answers). A default that arrives after load must not overwrite the person's choice (`chosen ?? default`, no effect).

**Dev-server trap:** a Vite dev server started from the agent sandbox receives NO file-change events — edits to TSX/CSS are silently not served. After editing, restart it (TaskStop + start again) before any screenshot. Playwright's own `webServer` starts fresh each run, so E2E and the screenshot recipe are unaffected.

**Visual review recipe (no usable MCP browser, see [[e2e-mock-mode-sandbox]]):** start the impostor, drop a throwaway spec in `e2e/_scratch/` that seeds data through the API fixtures (`signUpViaApi`, `createWalletViaApi`, `recordTransactionViaApi`) and `page.screenshot({ path: <abs scratchpad path>, fullPage: true })` for every state (`page.emulateMedia({ colorScheme, reducedMotion: 'reduce' })`, phone 390×780 + desktop 1280×800), run `bash .claude/scripts/run-with-env.sh E2E_MODE=mock -- bash .claude/scripts/run-e2e.sh _scratch list` (sandbox off), Read the PNGs, then `rm` the spec and `rmdir` the folder (`rm -r` is denied). Cover long content (60-char name, 200-char note, 15-digit Balance), negative figures, error and empty states, light AND dark. Contrast pairs are verified with a throwaway Node WCAG script (OKLab mix for `/70` opacities), not by eye. The live Web Interface Guidelines can be read with WebFetch of `raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md` (returns a paraphrase).
