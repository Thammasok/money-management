## Architecture Pattern

Pipeline skills reference **layer roles** rather than hardcoded layer names. This section maps those roles to your project's concrete layers.

| Role | Layer Name | Responsibility | Test Strategy |
|------|-----------|----------------|---------------|
| Entry Point | Controller (`*.controller.ts`) | Parse request, call business logic, return response | Mock Business Logic |
| Business Logic | Service (`*.service.ts`) | Domain rules, orchestration, data transformation | Mock Data Access, External Integration, Validation |
| Domain | Entity / value objects (`*.entity.ts`) | Pure domain types and invariants (e.g. money amounts, categories) | Nothing mocked |
| Data Access | Repository (`*.repository.ts`, using `pg`) | SQL queries, row ↔ entity mapping | Real Postgres via docker-compose |
| External Integration | Gateway (`*.gateway.ts`) | Calls to 3rd-party APIs (e.g. FX rates, bank feeds) | Real mock (Mountebank) |
| Real-Time | > Not applicable (no real-time requirement yet) | — | — |
| Validation | DTO + class-validator via `ValidationPipe` (`*.dto.ts`) | Input validation | Nothing mocked |

### Layer Dependency Flow
```
Controller → Service → Repository (pg)
                     → Gateway (HTTP)
           ↑ ValidationPipe (DTOs) runs before Controller
```

Proposed module layout (one Nest module per bounded context):
```
backend/src/{context}/
  {context}.module.ts
  {context}.controller.ts
  {context}.service.ts
  {context}.repository.ts
  {context}.gateway.ts          (only if the context calls an external API)
  dto/*.dto.ts
  {context}.entity.ts
  {context}.tokens.ts           (DI tokens)
  interfaces/*.interface.ts     (IService, IRepository, IGateway contracts)
```

### Reference: Architecture Patterns
| Role | REST/CRUD | GraphQL | Event-Driven | Real-Time Streaming |
|------|-----------|---------|-------------|-------------------|
| Entry Point | Controller | Resolver | EventHandler | SignalingHandler |
| Business Logic | Service | Service | Processor | SessionService |
| Data Access | Repository | Repository | EventStore | SessionStore |
| External Integration | Gateway | DataSource | Publisher | MediaServerGateway |
| Real-Time | WebSocket Gateway | Subscription | — | StreamGateway |
| Validation | Validator | InputType validators | Schema validator | Codec validator |

> **`run-eval.sh` (UX/UI evaluator) reads the frontend dev command from the line below** — keep it in sync with the "Dev server / Frontend" cell above. The dev script MUST honor the `$PORT` env var `run-eval.sh` exports (Vite: `vite --port $PORT`; Next: `next dev -p $PORT`; CRA reads `PORT`). If this line is absent, `run-eval.sh` falls back to `npm run dev`.
