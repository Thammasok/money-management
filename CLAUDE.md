## Project state

`money-management` is an application repo driven by the **saas-factory** XP agent harness. There is
**no application code yet** — no build, lint, or test commands exist. Once a stack is chosen, the
concrete commands and layer names live in `.claude/tech-stack-profile.md` (generated by
`/project:create-tech-stack-profile`); update this file with them then.

Repo layout today:

  `CLAUDE.md` and `README.md` are the full reference for the pipeline.
- `.claude/` — **real-file copies** of the harness `.claude/` (agents, commands, skills, hooks, rules,
  scripts, settings), produced by `sync-claude.sh`. Symlinks are not used — they break the Linux sandbox.
- `.mcp.json` — copied from the harness; servers are enabled and given credentials in
  `.claude/settings.local.json` (gitignored, holds secrets).
- `.gitmodules` still carries a stale `sass-factory` (typo) entry alongside `saas-factory`; only
  `saas-factory` is the live submodule.

## Harness maintenance

Harness-owned files under `.claude/` are overwritten on every sync — don't hand-edit them here; change
them upstream in saas-factory, then re-pin and re-sync:

```bash
git submodule update --remote saas-factory
bash saas-factory/.claude/scripts/sync-claude.sh
```

Fresh clone: `git submodule update --init --recursive` first. App-owned paths the sync never touches:
`.claude/agent-memory/`, `.claude/tech-stack-profile.md`, `.claude/settings.local.json`.
`.claude/settings.json` and `.claude/srt-settings.json` are two sandbox configs for two runtimes and
must stay in sync (`allowedDomains` / `denyRead` / `denyWrite`).

## Workflow entry points

Prime once per repo: `/init` (this file) then `/project:create-tech-stack-profile` — every pipeline
skill reads the profile and `/vibe-workflow` refuses to start without it.

- `/project:plan-epic "idea"` → drafts `epic.md`, `checklist.md`, `docs/ERD.md`, `docs/sequence.md`
  and grills the user until confirmed. Never implements.
- `/vibe-workflow` (or `/project:vibe`) → builds every confirmed feature autonomously (pre-dev →
  backend → frontend → deployment track agents, Stage 25.5 evaluator, epic-conformance gate); halts
  only on a Blocker or conformance DRIFT. Re-run to resume from the first not-Done feature.
- `/project:develop {feature}` → same 28 stages for one feature, pausing after each track.
- `/project:task "…"` → classifies non-epic work as feature / bugfix / chore / research and routes to
  `develop`, `develop-bugfix`, `develop-chore` (trivial tier = small fixes, no artifacts), or
  `develop-research`.

Each feature's `Surface` in `epic.md` (`full` / `backend-only` / `frontend-only`) decides which
tracks run.

## Fixed architecture & stack constraints (from the harness)

- Mockist unit tests at boundaries only; Data Access / External Integration are tested for real via

  API), FeatBit (flags).

## Rules that bind every session (`.claude/rules/`)

- **bash-discipline.md** — one command per Bash call, absolute paths, no `cd &&`, no `$(…)`, no
  env-var prefixes (use `bash .claude/scripts/run-with-env.sh KEY=VAL -- cmd`), no heredocs, no
  loops, background servers via `run_in_background`. Enforced by `.claude/hooks/bash-lint.py`.
- **E2E runs only as** `bash .claude/scripts/run-e2e.sh {feature} list`, spelled exactly in that
  relative form (sandbox exclusion matches the literal string).
- **git-flow.md** — branch `feat/` / `fix/` / `chore/` from `main`; never commit on `develop` or
  `main`; ship = `--no-ff` merge into `develop` (dev deploy) + PR to `main` via the GitHub MCP; never
  merge `develop` into `main` or into a working branch; abort (don't resolve) `develop` conflicts.
  No tags, force-pushes, or branch deletes.
- **No `gh` CLI for GitHub-side operations** — use GitHub MCP tools (only `gh auth status` allowed).
- **failure-protocol.md** — Stop on Blocker after the same failure twice; Fix Budget of 3 cycles per
  test file / 5 runs per stage; record Blockers in `artifacts/{feature}/track-handoffs.md`.
- `infra-discipline.md` and `pause-signal.md` only apply to the infra pipeline and headless Runner
  (`AGENT_RUNNER_PAUSE_SIGNAL=1`) respectively.

## Feature F-1: Sign Up and Sign In — DONE

Conformance: `artifacts/F-1/11-conformance-report.md` (CONFORMANT, 2026-10-29).

### Entities Introduced
- **User** (`users`): `id` (UUID, `gen_random_uuid()`), `email` (stored trimmed + lower-cased; UNIQUE
  `users_email_key` + CHECK `email = lower(email)`), `passwordHash` (argon2id, never leaves Identity),
  `createdAt`, `updatedAt`. **No `homeCurrency` yet** — F-10 adds the column, the field, and extends the guard.
- **Session** (`sessions`, Identity-internal): `id` = 32 random bytes base64url (the `sid` cookie value,
  stored raw), `userId` (FK cascade), `expiresAt` (30-day sliding, Postgres `now()`), `createdAt`.
- **Sign-in Attempt** (`sign_in_attempts`, Identity-internal): `email`, `attemptedAt`; no key, no FK.

### Key Decisions
- Every route is protected by the global `SessionGuard` (`APP_GUARD`); mark public routes `@Public()`, read
  the signed-in User with `@CurrentUser()` → `SignedInUser { userId }`. No module but Identity reads `users`;
  F-4's two lookups (User by email, emails by ids) are not built yet — add them to Identity's service.
- Request bodies must be `Content-Type: application/json` — anything else is **415** (login-CSRF hardening).
  Every Web App write must set the header (`HttpAuthService.send` does; reuse that pattern).
- 429 body = Nest default + `retryAt` (ISO-8601 UTC); the Web App renders the local time.
- Global `ValidationPipe` (`createValidationPipe()`, whitelist, `stopAtFirstError`); DTO 400 `message` is a
  `string[]`, other errors a `string`. Messages live in `*.messages.ts` constants.
- Liquibase: new changesets in `db/changelog/F-n/`, included from `db.changelog-master.yaml`; seed data
  `context: test` only; **production runs `--contexts=prod`** (an empty filter runs test seeds too).
- Backend: NestJS 11 + Jest 30 + TypeScript 6 (stay on `@nestjs/*@^11`). Runtime/CI Node 24.22.1 LTS — keep
  both Dockerfiles and `ci.yml` in step. Postgres on host port 15432 for dev/test.
- Frontend: DI via `ServiceProvider`/`useServices()` (add services to `Services`), `useSession()`,
  `RequireSignedIn` route nesting, `<PageHeading>`, `<ErrorAlert>`, `<TextField>`; design tokens only in
  `frontend/src/styles/theme.css`. SPA and `/api/v1` are served from one origin (no CORS).
- Add each feature's routes to `scripts/smoke-test.sh`; new backend env vars go in `docker-compose.yml`,
  `backend/.env.example`, and `.env.example`.

### Failed Approaches (Do Not Retry)
- NestJS 12 under Jest: ESM-only packages need `--experimental-vm-modules`; transforming to CJS fails on
  `import.meta`. Upgrading is a dedicated ESM + Vitest chore.
- Node 22 base images: its npm 10 rejects the npm-12-written `backend/package-lock.json`.
- `npm run db:*` inside an agent sandbox (Docker via npm is blocked) — run `docker compose …` directly.
- Mock-mode E2E through `run-with-env.sh` runs sandboxed and Chromium dies — needs the sandbox off.

### Blockers for Next Feature

## Feature F-2: Record Income and Expense in a Wallet — DONE

Conformance: `artifacts/F-2/11-conformance-report.md` (CONFORMANT, 2026-10-29).

### Entities Introduced
- **Wallet** (`wallets`, Ledger): `id`, `userId` (FK RESTRICT), `name` (trimmed, 1–60 code points, CHECK),
  `currency` (`char(3)`, from the snapshot, fixed), `openingBalanceMinor` (BIGINT, may be ≤ 0), `createdAt`,
  `updatedAt`. Balance derived in SQL (`SELECT_WALLET_WITH_BALANCE`, NUMERIC → text). No `archivedAt` yet (F-3).
  The API body omits `userId`.
- **Transaction** (`transactions`, Ledger): `id`, `walletId` (FK RESTRICT), `kind` (CHECK income/expense),
  `amountMinor` (BIGINT > 0), `occurredOn` (DATE as exact `YYYY-MM-DD` string), `note` (≤ 200, blank → null),
  `createdAt`, `updatedAt`. No `recordedByUserId` (F-4) or `categoryId` (F-8) yet.
- **Currency** (Exchange Rates, not a table): `{ code, name, minorDigits }`, a frozen 30-entry snapshot in
  `backend/src/rates/supported-currencies.ts` (BGN dropped; JPY/ISK/KRW 0 digits). It must be kept in step with
  `mocks/ledger-api.inject.js`.

### Key Decisions
- Routes: `GET /currencies`, `GET|POST /wallets`, `GET /wallets/:walletId` (Wallet + Balance + all
  Transactions), `POST /wallets/:walletId/transactions` (body includes `today`; returns the Transaction only, and the
  Web App re-reads the Wallet). `GET /wallets` is a minimal list (no Balances); F-3 extends it.
- Visibility is one SQL constant, `WALLET_IS_VISIBLE` in `ledger.repository.ts` (F-4 widens it). The F-3 archived
  409 goes in `LedgerService.recordTransaction` after the 404 (a comment marks the spot). A malformed id is 404,
  never `ParseUUIDPipe`.
- Every `pg` Pool comes from `database/create-pool.ts` (DATE → string, BIGINT/NUMERIC stay strings); tests use
  `createTestPool()`. Wallet detail reads in one REPEATABLE READ READ ONLY snapshot.
- Reuse `ledger/validation/validators.ts` (`IsCalendarDate`, `IsNotAfter`, `IsPositiveMinorUnits`,
  `IsWithinMinorUnitLimit`, `MaxCharacters`) and `dto/clean-text.ts`. Use `MaxCharacters`, not `@MaxLength`,
  wherever a DB CHECK counts characters. Amounts are capped at 15 digits.
- The shared `createValidationPipe()` answers a too-deeply-nested body with 400 (string `message`).
- Frontend: `Services = { authService, walletService }`; shared HTTP helpers live in `frontend/src/services/http/`.
  Money uses `toMinorUnits` / `formatMinor` (`en-US`, Currency code, digits from `GET /currencies`, formatted from
  the string so values beyond 2^53 stay exact). `localToday()` uses getFullYear/getMonth/getDate, never
  `toISOString`. Add F-3's 409 (and maybe 429) to `SHOWN_AS_SENT` in `wallet-messages.ts`.
- Edge: nginx `ledger_writes` limits writes under `/api/v1/wallets` (60/min per address). Run one backend replica.
- Starting the backing stack for API calls: `up -d --wait postgres`, then `run --rm -T migrations` (`up --wait`
  does not wait for the Liquibase one-shot).

### Failed Approaches (Do Not Retry)
- Setting `process.env.TZ` inside a Jest test does not change the process zone (H-13). Set it in the Jest config,
  or run the process with `TZ`.
- class-validator `@MaxLength` counts differently from Postgres `char_length` (variation selectors), which turns
  into 500s on CHECK constraints.
- A bare `docker compose up -d --wait` before calling the API races Liquibase (`relation "users" does not exist`).
